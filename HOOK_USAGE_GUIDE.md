Optional gas sponsorship via ERC‑4337 paymaster

If you want a third party to pay gas (the paymaster contract) then you
**do not** need a private key – a paymaster is an on‑chain contract. Your
backend simply needs to send the call through an ERC‑4337 bundler that will
attach the paymaster address when it constructs the UserOperation. Set the
`BUNDLER_URL` (or `PIMLICO_BUNDLER_URL`) environment variable to point at a
service that understands your paymaster logic. The `PAYMASTERS` list in
`/supabase/functions/_shared/mainnet-config.ts` contains candidate addresses;
the first one is selected automatically.

To activate the feature you must also set a bundler URL in the Supabase
environment (or locally in `.env`). For example:

```bash
export BUNDLER_URL=https://example-bundler.mycompany.com/relay
# or use Pimlico’s hosted bundler:
export PIMLICO_BUNDLER_URL=https://bundler.pimlico.io/relay
```

The bundler service takes a minimal JSON payload and returns a `taskId` or
`userOpHash`. You can deploy your own by extending `supabase/functions/gasless-relay`.

Our sample `supabase/functions/gasless-relay` function can be extended into
such a bundler, or you can use Pimlico's hosted bundler. Without a bundler,
the backend will fall back to Gelato relay or throw a "missing bundler"
error when paymaster mode is enabled.
